# VVD 3.0 - десктоп-клиент (Windows)

Тонкий десктоп-клиент CRM VVD 3.0 на Electron. По сути это окно, в котором
открывается боевой сайт `https://formulavvd.com` - весь функционал тот же, что
и на сайте. Вход сохраняется между запусками.

При запуске сразу открывается страница входа (если пользователь не авторизован)
или дашборд `/home` (если уже вошёл). Лендинг в приложении не показывается.

## Требования

- Node.js 20+ (рекомендуется LTS)
- Windows - для сборки установщика `.exe`

## Установка зависимостей

```bash
npm install
```

## Запуск в режиме разработки

```bash
npm start
```

Откроется окно приложения с сайтом. Это самый быстрый способ проверить клиент -
сборка установщика для этого не нужна.

## Белый экран и восстановление после него

У Electron нет своей страницы «что-то пошло не так». Если страница не
загрузилась или умер процесс её отрисовки, остаётся **пустое белое окно**:
меню на месте, страницы нет, и сама она не вернётся - даже когда интернет
восстановится. Для человека это выглядит как «программа сломалась», хотя
сервер цел и все данные на месте.

Так и случилось у центра SMART KIDS 24.08.2026: на минуту пропал интернет
ровно в момент перехода между разделами - белое окно продержалось почти час,
пока приложение не закрыли и не открыли заново.

С версии **1.0.15** этим занимается `attachRecovery()` в `src/main.js`:

| Событие | Что делаем |
|---|---|
| `did-fail-load` - страница не загрузилась | 5 тихих повторов раз в 6 секунд. Короткий обрыв связи человек не заметит. Не помогло - диалог «Повторить / Выход» |
| `render-process-gone` - умер процесс отрисовки | Возвращаем окно на последний рабочий адрес, до 3 раз подряд; дальше диалог |
| `unresponsive` - окно повисло | Спрашиваем: подождать или перезагрузить |

Причина сбоя уходит на сервер (`/api/desktop/crash`) - иначе о таких случаях
не узнаёт никто: со стороны сервера это выглядит просто как тишина, запросы
перестают приходить, ошибок нет.

⚠️ **Грабля, на которой уже наступили.** Событие `did-finish-load` приходит и
ПОСЛЕ неудачной загрузки: Electron дорисовывает вместо страницы пустую
заглушку и честно сообщает, что закончил. Если принять это за успех, обработчик
отменяет собственный же повтор - и окно остаётся белым навсегда. Поэтому есть
флаг `loadFailed`, который ставит `did-fail-load` (он приходит раньше) и
сбрасывает `did-start-loading`. Именно эту ошибку поймала проверка ниже.

### Проверка восстановления

```bash
npm run test:recovery
```

Два прогона с НАСТОЯЩИМ клиентом на локальном сервере:

1. `test-offline-recovery.js` - гасит сервер в момент перехода между
   страницами, ждёт повторов, поднимает сервер обратно и проверяет, что окно
   вернулось само;
2. `test-crash-recovery.js` - убивает процесс отрисовки клиента (строго внутри
   его дерева процессов, чужие Electron-приложения на машине не трогает) и
   проверяет, что окно вернулось на ту же страницу.

На Linux окну нужен экран, поэтому запускать под `xvfb-run -a npm run
test:recovery`. Проверки ничего не устанавливают и в интернет не ходят: адрес
сайта подменяется переменной `VVD_APP_URL`, которая работает ТОЛЬКО в
неупакованном приложении.

## Сборка установщика для Windows

1. Сгенерировать иконку `.ico` из логотипа (один раз или после смены логотипа):

   ```bash
   npm run icon
   ```

2. Собрать установщик:

   ```bash
   npm run dist
   ```

Готовый установщик появится в папке `dist/` - файл вида
`VVD-3.0-Setup-1.0.0.exe`. Его можно запускать и устанавливать.

> Примечание: приложение пока без цифровой подписи, поэтому при первой установке
> Windows может показать предупреждение SmartScreen «неизвестный издатель» -
> нужно нажать «Подробнее → Выполнить всё равно». На работу это не влияет.

```

├── src/main.js          # основной процесс: окно, меню, внешние ссылки,

├── build/icon.ico       # иконка Windows (генерируется из icon.png)
├── electron-builder.yml # конфигурация сборки
└── package.json
```
